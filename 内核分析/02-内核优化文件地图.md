# 内核优化文件地图:调度器与内存碎片回收

> 配套文档: 《RK3568内核调度器分析报告.md》(分析结论)
> 源码根: `~/2024204088/OHOS501/kernel/linux/linux-5.10`(Linux 5.10.208,OpenHarmony 5.0.1 适配版)
> 目标板: RK3568(4×Cortex-A55,无 big.LITTLE)

## 一、进程/系统调度优化涉及文件

### 1.1 文件清单与作用

| 文件 | 大小 | 作用与切入点 |
|---|---|---|
| `kernel/sched/fair.c` | 328K | **主战场**。CFS 全部算法: `vruntime` 计算、`wakeup_preempt_entity`(唤醒抢占阈值)、`load_balance`(负载均衡)、`update_cfs_rq_load_avg`(PELT 挂载)、`h_load`。改抢占/均衡/粒度均在此 |
| `kernel/sched/core.c` | 236K | 调度器入口 `schedule()`、`wake_up_process()`、`nice_to_weight`、cgroup 调度、`__schedule` 主循环 |
| `kernel/sched/sched.h` | 84K | 核心数据结构: `struct sched_entity`、`struct rq`、`struct cfs_rq`、`struct task_struct` 调度字段。**加字段/统计必须动这里** |
| `kernel/sched/rt.c` | 76K | RT 调度: `rt_effective_prio`、`check_preempt_curr_rt`、RT 带宽控制 |
| `kernel/sched/topology.c` | 64K | 调度域拓扑: sd 层级构造、`group_imb`(组不平衡判定)、`SD_*` 标志,多核/不对称亲和在此配置 |
| `kernel/sched/psi.c` | 40K | 压力信号(CPU/IO/内存),**优化效果的观测指标源**(/proc/pressure/) |
| `kernel/sched/cpufreq_schedutil.c` | 28K | 调度与调频联动: `update_util_data`、wakeup 负载→频率抬升,影响功耗/响应 |
| `kernel/sched/core_ctl.c` | 28K | **Rockchip 适配特有**:CPU 在线/下线控制、实时负载预测(全志/瑞芯微生态优化热点) |
| `kernel/sched/pelt.c` / `pelt.h` | 16K | PELT 负载跟踪: `___update_load_avg`、衰减周期(改周期=改负载灵敏度) |
| `kernel/sched/idle.c` | 16K | 空闲任务 `idle_balance`(唤醒时越界拉任务)、节能 |
| `kernel/sched/features.h` | 4K | **特性开关**(性价比最高): `GENTLE_FAIR_SLEEPERS`、`NEXT_BUDDY`、`LAST_BUDDY`、`WAKEUP_PREEMPTION` 等,改一行立即改变调度行为 |
| `kernel/sched/rtg/` | 112K | RK 的 RTG(实时任务组)调度扩展 |
| `kernel/sched/sched_avg.c` | - | RK 扩展的负载平均统计 |
| `include/linux/sched.h` + `include/linux/sched/*.h` | - | `struct task_struct`、`sched_attr`、`SCHED_*` 常量定义 |
| `Documentation/scheduler/` | - | CFS/PELT 算法说明文档(读算法先看这里) |
| `arch/arm64/configs/rk3568_*_defconfig` | - | `CONFIG_SCHED_*`、`CONFIG_PSI`、`CONFIG_FAIR_GROUP_SCHED` 等开关 |

`sched` 目录合计 **1.4M**,其中上表核心文件约 476K(不含 rtg 112K)。

### 1.2 建议的修改起点(按改动量排序)

1. `kernel/sched/features.h` — 开关级实验(零代码量)
2. `kernel/sched/fair.c` 中 `wakeup_preempt_entity()` — 抢占阈值(如 `wakeup_gran`)
3. `kernel/sched/fair.c` 中 `update_min_vruntime` / `__update_load_avg` — 虚拟时间/负载算法
4. `kernel/sched/core.c` 中 `wake_up_process` 的 `WF_SYNC` 处理
5. `kernel/sched/psi.c` 阈值与窗口 — 同时提供可量化的效果对比

### 1.3 验证手段

- `/proc/schedstat`、`/proc/sched_debug`(调度统计)
- `/proc/pressure/cpu`(PSI 压力)
- `perf sched`(若内核开 PERF)
- 真实负载: 编译内核/解压/多线程基准(lmbench/cyclictest)

## 二、内存碎片回收优化涉及文件

### 2.1 文件清单与作用

| 文件 | 大小 | 作用与切入点 |
|---|---|---|
| `mm/page_alloc.c` | 252K | **主战场**。伙伴系统: `__alloc_pages` 主路径、`rmqueue`(按迁移类型取块)、`zone_watermark_ok`、`buffered_rmqueue`、`pageblock` 迁移类型管理、`get_page_from_freelist` |
| `mm/slub.c` | 144K | SLUB 对象缓存(kmalloc): `kmem_cache_alloc`、`slab_order`、`cpu_partial`。**对象级碎片是隐形大户** |
| `mm/vmscan.c` | 128K | LRU 回收: `shrink_node`、`kswapd`、`should_continue_reclaim`、`scan_control` 参数(扫描比例/优先级) |
| `mm/compaction.c` | 84K | **碎片整理引擎**: `compact_zone`、`migrate_pages` 触发、`compact_skipped`、`fragmentation_index`(碎片指数计算) |
| `mm/migrate.c` | 84K | 页迁移实现(compaction 的内核, `unmap_and_move`) |
| `mm/vmstat.c` | 56K | 内存统计(碎片率、迁移类型分布观测源, `/proc/vmstat`、`/proc/buddyinfo`) |
| `include/linux/mmzone.h` | 48K | `struct zone`、`struct free_area`、`MIGRATE_*` 迁移类型定义、`zone_watermarks`。**加迁移类型/改水线要动这里** |
| `mm/cma.c` | 16K | CMA 连续内存(RK3568 多媒体/GPU 依赖, `cma_alloc` 失败是碎片常见表现) |
| `mm/page_isolation.c` | 12K | 页块隔离(CMA/大块分配的底层) |
| `include/linux/pageblock-flags.h` | 4K | 页块迁移类型标志位 |

`mm` 目录合计 **4.4M**,上表核心文件约 828K。

### 2.2 建议的修改起点(按改动量排序)

1. `mm/vmstat.c` + `/proc/buddyinfo` — 先摸清碎片现状(观测先行)
2. `mm/compaction.c` 的 `compact_skipped` / `fragmentation_index` — 调整碎片整理触发阈值
3. `mm/page_alloc.c` 的 `__free_one_page`(合并方向)与 `rmqueue`(迁移类型回退策略 `fallback` 数组)
4. `mm/vmscan.c` 的 `SWAP_CLUSTER_MAX` / `sc->priority` 扫描节奏
5. `mm/slub.c` 的 `slab_order`/`min_order`(碎片率敏感型负载)

### 2.3 验证手段

- `/proc/buddyinfo`(各迁移类型块分布,碎片直观)
- `/proc/vmstat`(`compact_*`、`allocstall_*`、`pgalloc_*` 计数)
- `/proc/pressure/memory`(内存压力)
- 大块分配成功率: 反复 `malloc 大块` + CMA 分配测试
- `mm/page_owner`(CONFIG_PAGE_OWNER 开启后定位碎片来源)

## 三、两个主题的配合点(竞赛演示建议)

1. **调度**: 唤醒抢占阈值 + PELT 负载周期 → 降低 `runqueue latency` / PSI cpu
2. **内存**: compaction 触发阈值 + 迁移类型回退 → 提高大块连续内存可用率
3. 联动: RK3568 的 `core_ctl`(核调度)与 `cma.c` 关系紧密(核上线需内存),可做"调度+内存"组合优化,演示更完整

## 四、通用注意事项

- 改完内核: `./build.sh --product-name rk3568` 增量编译内核即可(out 保留着 obj 缓存,约几分钟)
- 每次修改前 `git diff` 留档;建议按主题分开提交,便于竞赛答辩展示演进过程
- 内核配置开关确认: `arch/arm64/configs/` 下 rk3568 的 defconfig 中 `CONFIG_COMPACTION`、`CONFIG_PSI`、`CONFIG_FAIR_GROUP_SCHED` 需为 y
