# 复现指南

## 环境和基线

使用 Linux x86_64 宿主机、QEMU system aarch64 和 OpenHarmony 5.0.1 的 `qemu-arm64-linux-min` 产品。内核为 Linux 5.10.208，参考基线提交为 `8d8762e824a04bd99b37e5cd635919ea926c8357`。预编译工具链为 OHOS clang 15.0.4 和 Linaro aarch64 GCC 7.5 工具链中的 binutils。完整源码及 prebuilts 需按 OpenHarmony 对应版本文档下载，不在本仓库重复分发。

本机已有完整工作区为 `/home/dark/2024204088/OHOS501`。新的环境须先运行 OpenHarmony 官方依赖安装和 prebuilts 下载步骤。整个系统构建对工具链和依赖敏感，不能仅用主机发行版任意 clang 替换。

## 覆盖源码

```bash
python3 scripts/apply_snapshot.py /path/to/OHOS501
# 确认版本及已有本地更改后执行，脚本会保留被覆盖文件的备份
python3 scripts/apply_snapshot.py /path/to/OHOS501 --apply
cd /path/to/OHOS501
./build.sh --product-name qemu-arm64-linux-min --ccache
```

`repo/` 相对于 OpenHarmony 根目录。另一种方式是在独立 linux-5.10 基线树运行 `git apply --check` 后应用 `evidence/linux-5.10-eevdf-qos.patch`，并另外复制 common_modules、config、vendor 文件。两种方式二选一，不能重复应用。

最终配置应包含 `CONFIG_QOS_CTRL=y`、`CONFIG_AUTHORITY_CTRL=y`、`CONFIG_FAIR_GROUP_SCHED=y`、`CONFIG_SCHED_HRTICK=y`、`CONFIG_HZ=250`。HRTICK 编译选项开启并不代表运行时特性启用，当前 `features.h` 中 HRTICK 默认关闭、RUN_TO_PARITY 默认开启。本次镜像为历史构建 #15 EEVDF 与 #12 CFS；输入哈希在 evidence/images.json。

完整系统构建会准备 `out/KERNEL_OBJ/kernel/src_tmp/linux-5.10` 并合入 OpenHarmony 适配。已有配置与准备好的源码可增量编译内核，但不能在未经准备的裸内核目录中期待直接得到相同系统镜像。原工作区构建环境修复记录见 `进度文件夹/qemu构建修复记录.md`（本地历史资料）。

## 两个独立内核

EEVDF 镜像来自本项目快照。CFS 对照须使用同一 OHOS、配置和工具链，在独立准备树中恢复基线调度器与头文件，保留 `sched_cmp_bench.c`，并在 `kernel/sched/Makefile` 加入 `obj-y += sched_cmp_bench.o`。CFS 树不要编译依赖 EEVDF 私有字段的 `qos_slice_bench.o`。两棵树应独立输出，避免时间戳造成错误复用。历史对比遵循此方法，本次直接复跑已保留的两颗镜像，没有声称重新执行了全量构建。

准备同一镜像目录：`Image-eevdf`、`Image-cfs`、`ramdisk.img`、`system.img`、`vendor.img`、`userdata.img`、`updater.img`。用户态镜像来自已有 QEMU 最小系统构建。官方构建完成后一般位于 `out/qemu-arm-linux/packages/phone/images`，以实际产品输出为准。比较时仅切换内核，其他镜像保持相同哈希。

## 运行及判定

```bash
python3 scripts/run_bench.py --images /path/to/images --mode qos --seconds 100 --output /tmp/qos-new
python3 scripts/run_bench.py --images /path/to/images --mode boot --seconds 35 --output /tmp/boot-new
python3 scripts/run_bench.py --images /path/to/images --kernel cfs --mode compare --seconds 65 --output /tmp/cfs-new
python3 scripts/run_bench.py --images /path/to/images --kernel eevdf --mode compare --seconds 65 --output /tmp/eevdf-new
```

QEMU 使用 `-snapshot` 临时磁盘覆盖层，关闭网络，不创建网桥，不需要 sudo。脚本拒绝覆盖已有证据文件。输出 JSON 保存完整命令、QEMU 版本、镜像哈希、串口哈希、测试记录和完成标志。宿主定时终止是预期行为，不等于客户机崩溃。慢速机器应增加时限，特别是 QoS 检查必须等到客户机 60 秒扫描完成。

QoS 模式要求 QoS、FORK、REWEIGHT 和 AVG done 四项 pass。比较模式要求完整 done；检查每种延迟场景 300 样本、两种公平性场景和 pingpong，按多次启动分别汇总。boot 模式不传测试启动参数，应无 EEVDF 测试输出且 samgr 就绪。用户态最小镜像可能有 watchdog_service 重启等日志，必须与内核 BUG/Oops/RCU stall 区分。

本次实验运行过程、结果和局限见实验结果文档。所有时间为 TCG 客户机时钟，禁止换算为硬件应用性能。
